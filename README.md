# Ассемблер УВМ: вариант №2, этапы 1–2

Приложение на Go переводит программу в формате JSON в промежуточные
команды, затем формирует машинный код и записывает его в двоичный файл.
После записи выводится размер файла в байтах. Тестовый режим дополнительно
выводит байты каждой команды в формате примеров спецификации.
Поддержаны все четыре команды: загрузка константы, чтение, запись и `pow()`.

## Сборка и запуск

Требуется Go 1.22 или новее. Используется только стандартная библиотека;
установка сторонних зависимостей не требуется. Команды выполняются
из корня проекта.

```sh
make build
./build/assembler --test examples/specification.json build/program.bin
```

Без предварительной сборки:

```sh
go run ./src --test examples/specification.json build/program.bin
```

Команды Make:

| Команда | Действие |
| --- | --- |
| `make build` | Собрать исполняемый файл `build/assembler` |
| `make run` | Собрать машинный код программы и вывести размер файла |
| `make demo` | Собрать пример, вывести размер файла и байты команд |
| `make test` | Запустить автоматические тесты |
| `make check` | Запустить тесты, `go vet` и проверку `gofmt` |

Настройки Make: `GO` — команда Go (по умолчанию `go`),
`SOURCE` — исходный файл (по умолчанию `examples/specification.json`),
`OUTPUT` — путь машинного кода (по умолчанию `build/program.bin`).

```sh
make demo SOURCE=examples/specification.json OUTPUT=build/program.bin
```

Исполняемый файл приложения и двоичный файл программы УВМ — разные
файлы. `build/assembler` запускается операционной системой,
а `build/program.bin` содержит команды учебной машины.
Команды Make создают каталог `build`. При прямом запуске приложения
или выборе другого `OUTPUT` родительский каталог результата должен
существовать. Существующий результат заменяется при успешной трансляции.
Сборка и машинный код исключены из git через `.gitignore`.

## Интерфейс командной строки

```text
assembler [--test] source.json output.bin
```

| Параметр | Назначение |
| --- | --- |
| `source.json` | Обязательный путь к исходной программе в UTF-8 |
| `output.bin` | Обязательный путь двоичного результата |
| `--test`, `-test` | Дополнительно вывести байты каждой команды |
| `--help`, `-h` | Показать справку |

Переключатель `--test` можно указать до или после путей.
Пути с пробелами передаются в кавычках. Справка и ошибки направляются
в stderr, размер файла и байты команд — в stdout. Без `--test` выводится
только размер файла. В тестовом режиме сначала выводится размер,
затем по одной строке байтов на команду.

Исходник полностью проверяется до записи результата. Ошибочная программа
не изменяет существующий выходной файл и не выводит частичный результат.
Запись поверх исходного файла запрещена, включая совпадение через ссылки.
Пустой массив создает файл размером 0 байт. При ошибке записи файла
размер и байты не выводятся. Ошибка stdout возвращается после сохранения
двоичного результата.

Коды завершения исполняемого файла: `0` — успех или справка,
`1` — ошибка чтения, программы, записи файла или stdout,
`2` — неверные аргументы командной строки. Обертка `go run` при ошибке
приложения может возвращать собственный код и печатать `exit status`.

## Язык ассемблера

Программа — массив объектов JSON. Поле `op` задает мнемонику команды;
остальные поля задают именованные операнды. Порядок команд сохраняется,
порядок ключей объекта не важен. Пустой массив допустим.

Мнемоники записываются заглавными буквами. Имена полей чувствительны
к регистру. Лишние, пропущенные и повторяющиеся ключи запрещены.
Комментарии и завершающие запятые не поддерживаются синтаксисом JSON.

| Мнемоника | Поля JSON | Поля УВМ |
| --- | --- | --- |
| `LOAD` | `op`, `value` | `A=24`, `B=value` |
| `READ` | `op`, `address` | `A=46`, `B=address` |
| `WRITE` | `op` | `A=38` |
| `POW` | `op`, `operand_offset`, `result_offset` | `A=61`, `B=operand_offset`, `C=result_offset` |

| Операнд | Разрядность | Допустимый диапазон |
| --- | --- | --- |
| `value` | 8 бит | 0..255 |
| `address` | 31 бит | 0..2147483647 |
| `operand_offset` | 11 бит | 0..2047 |
| `result_offset` | 11 бит | 0..2047 |

Операнды задаются неотрицательными целыми числами JSON в десятичной
записи без дробной части и экспоненты. Строки, логические значения,
массивы, объекты и `null` вместо чисел запрещены. Код операции `A`
определяется по мнемонике и в исходном объекте не указывается.

Назначение команд согласно варианту:

- `LOAD` помещает константу `B` на стек.
- `READ` помещает значение памяти по адресу `B` на стек.
- `WRITE` снимает значение, затем адрес со стека и записывает значение
  в память по этому адресу.
- `POW` снимает первый операнд, базовый адрес второго операнда и базовый
  адрес результата со стека. Второй операнд берется из памяти по своему
  базовому адресу плюс `B`; результат предназначен для памяти по базовому
  адресу результата плюс `C`.

На этапах 1–2 стек, память и вычисления не исполняются. Пример ниже
проверяет трансляцию отдельных команд из спецификации.

## Пример из задания

Файл `examples/specification.json`:

```json
[
  {"op": "LOAD", "value": 38},
  {"op": "READ", "address": 309},
  {"op": "WRITE"},
  {"op": "POW", "operand_offset": 180, "result_offset": 1}
]
```

Запуск `make demo` выводит:

```text
Размер двоичного файла: 12 байт
0x98, 0x09
0x6E, 0x4D, 0x00, 0x00, 0x00
0x26
0x3D, 0x2D, 0x02, 0x00
```

Файл `build/program.bin` содержит эти 12 байт подряд, без заголовков,
разделителей и переводов строк. Текстовый эталон байтов сохранен
в `examples/expected-bytes.txt`. Файл `examples/expected.txt` сохраняет
эталон промежуточных полей первого этапа; соответствующие тесты сохранены.
Все поля и байты соответствуют примерам варианта №2.

## Формирование машинного кода

| Команда | Поле A | Поле B | Поле C | Размер |
| --- | --- | --- | --- | --- |
| `LOAD` | Биты 0–5 | Биты 6–13 | Отсутствует | 2 байта |
| `READ` | Биты 0–5 | Биты 6–36 | Отсутствует | 5 байт |
| `WRITE` | Биты 0–5 | Отсутствует | Отсутствует | 1 байт |
| `POW` | Биты 0–5 | Биты 6–16 | Биты 17–27 | 4 байта |

Команда формируется побитовыми сдвигами и объединением через `OR`:
`A | (B << 6)` и для `POW` дополнительно `| (C << 17)`.
В коде ширины, сдвиги, размеры команд и число битов в байте объявлены
именованными константами. Порядок байтов — little-endian:
первым записывается младший байт. Незанятые старшие биты равны нулю.
Длина каждой команды фиксирована спецификацией и не сокращается,
когда операнды равны нулю.

## Устройство реализации

Промежуточное представление имеет тип `[]Instruction`.
Каждая `Instruction` содержит срез `Fields` из элементов `Field`.
Поле хранит `Name` типа `string` и `Value` типа `uint64`.
Порядок полей фиксирован: `A`, затем существующие `B` и `C`.

`specification.go` содержит именованные константы кодов операций,
разрядностей, сдвигов и размеров команд, основание десятичной записи,
мнемоники и имена полей.
Максимумы операндов вычисляются из разрядности по формуле `2^n - 1`.
Коды завершения, позиции аргументов и параметры разбора также объявлены
именованными константами. Числа в примере и эталонах — данные задания.

Кодировщик получает `[]Instruction` и возвращает `[][]byte`, сохраняя
границы двоичных команд для тестового вывода. При записи команды
объединяются в непрерывную последовательность байтов. Кодировщик также
проверяет промежуточные поля: код операции, количество, порядок,
имена и диапазоны значений. Ошибка не возвращает частичный машинный код.
Для нового выходного файла используется режим доступа `0644`
с учетом системной маски прав; эта настройка объявлена константой.

| Функция | Назначение |
| --- | --- |
| `main` | Передать аргументы и стандартные потоки приложению |
| `Run` | Запустить приложение и вернуть код завершения |
| `normalizeArguments` | Разрешить переключатель тестирования после путей |
| `parseArguments` | Проверить аргументы и подготовить параметры запуска |
| `assembleFile` | Прочитать JSON, перевести, закодировать и сохранить программу |
| `saveProgram` | Записать байты, запретив перезапись исходника |
| `writeResult` | Вывести размер файла и байты команд в тестовом режиме |
| `Translate` | Проверить UTF-8, разобрать JSON и перевести все команды |
| `readCommands` | Прочитать массив команд и запретить данные после него |
| `expectOpening` | Проверить открывающий разделитель массива или объекта |
| `readCommand` | Прочитать объект команды, запретив повторяющиеся ключи |
| `expectEnd` | Проверить конец исходного документа |
| `commandSpecification` | Проверить мнемонику и точный набор полей |
| `translateCommand` | Проверить операнды и сформировать поля команды |
| `findSpecification` | Найти код операции и описание операндов |
| `findOpcodeSpecification` | Найти описание команды по числовому коду |
| `operandSpec.maximum` | Вычислить максимум значения поля |
| `Instruction.String` | Представить команду в текстовом формате задания |
| `encodingSpecification` | Проверить заголовок и число промежуточных полей |
| `EncodeInstruction` | Упаковать поля одной команды в байты little-endian |
| `Encode` | Перевести всю промежуточную программу в двоичные команды |
| `FormatBytes` | Представить байты в формате `0x98, 0x09` |

Все функции снабжены комментариями Godoc. Функции ограничены
40 строками, число параметров не превышает 7, строки Go-кода
не превышают 120 символов.

## Тестирование

```sh
go test ./... -v
go vet ./...
```

Тесты в `tests/` проверяют:

- Поля и текстовое представление всех команд из спецификации.
- Точные байты каждой команды, их длины и итоговый размер файла 12 байт.
- Упаковку максимальных значений, переносы между байтами и резервные биты.
- Ошибки промежуточных полей, включая диапазоны и порядок.
- Обе границы каждого операнда и выход за них.
- Недопустимые типы, ошибки JSON и неверные наборы полей.
- Повторяющиеся ключи и лишние данные после программы.
- UTF-8, пустую программу, порядок команд и номер команды в ошибке.
- Аргументы CLI, справку, оба режима и ошибки чтения и вывода.
- Создание и замену двоичного файла, размер и содержимое на диске.
- Отсутствие частичного вывода и сохранность результата при ошибках входа.
- Пустую программу, недоступный выходной путь и защиту исходника от перезаписи.
- Сборку и запуск отдельного исполняемого файла с путями с пробелами.

`readFixture` читает эталоны, `writeFixture` создает временные данные,
`runCLI` перехватывает потоки и код завершения,
`buildExecutable` собирает приложение во временный каталог теста.
`decodeHex` читает независимый текстовый эталон байтов,
`expectedByteCommands` возвращает отдельные эталонные команды,
`expectedMachineCode` объединяет их, `expectedCLIOutput` добавляет
ожидаемую строку размера, `assertMachineCode` проверяет файл на диске,
`assertSourceProtected` проверяет отказ перезаписи исходника.
Каждый тест имеет комментарий с описанием проверяемого поведения.
Тестовые данные и результаты сборки создаются во временных каталогах.
